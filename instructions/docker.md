# Docker-автоматизация

1. Команда `docker compose up -d --build` читает `docker-compose.yml` и запускает описанную в нём инфраструктуру.
2. Compose объединяет сервисы `postgres`, `chroma`, `django` и `nginx` в один проект и создаёт для них общую сеть.
3. PostgreSQL запускается из готового образа `postgres:15-alpine`, потому что собирать собственный образ базы не требуется.
4. Параметры базы передаются из `.env`, а bind mount сохраняет её данные вне файловой системы контейнера.
5. Healthcheck выполняет `pg_isready`, потому что запущенный процесс PostgreSQL ещё не обязательно готов принимать подключения.
6. Chroma запускается из готового образа `chromadb/chroma:1.5.0`, а её данные также сохраняются через bind mount.
7. Порты PostgreSQL и Chroma не публикуются на хост, потому что к этим сервисам обращается только backend по внутренней сети.
8. Django ждёт здоровый PostgreSQL и запущенный Chroma благодаря условиям в `depends_on`.
9. Для Django нет готового стороннего образа с кодом проекта, поэтому Compose собирает `rag-project:latest` по `Dockerfile`.
10. Dockerfile берёт `python:3.12` и создаёт рабочую директорию `/app`, чтобы подготовить одинаковое Python-окружение на любом хосте.
11. Сначала в образ копируется `requirements.txt` и устанавливаются зависимости, чтобы Docker мог кешировать этот долгий шаг.
12. Затем копируется код проекта, а `.dockerignore` не позволяет добавить в образ секреты, локальные данные и кеши.
13. Готовый backend-образ запускает Gunicorn, потому что встроенный сервер Django не предназначен для production-запуска.
14. После Django запускается Nginx на внешнем порту `8080`, а первый запуск завершается применением миграций и сбором статики через `collectstatic`.
